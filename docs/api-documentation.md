## 1. Conventions

### 1.1 Transport and format
- HTTPS only in production; JSON request/response bodies (`Content-Type: application/json`), UTF-8.
- `PATCH` is partial; `PUT` is not supported (`405`).
- Dates: `YYYY-MM-DD`. Datetimes: ISO 8601 UTC with `Z` (`2026-10-31T14:05:00Z`).
- IDs: UUID v4 strings, lowercase, hyphenated.
- Unknown body fields are rejected (`400 unknown_field`) to catch client bugs.
- Every response includes `X-Request-ID`; clients may send `X-Request-ID` (UUID) to correlate.

### 1.2 Authentication model
- Session cookie `sessionid` (`HttpOnly`, `SameSite=Lax`, `Secure` in production).
- CSRF: `GET /auth/csrf/` sets a `csrftoken` cookie (JS-readable). All `POST`/`PATCH`/`DELETE` requests must send `X-CSRFToken` with that value.
- Public token endpoints (§7.10, §8.6, §14.11) require no session and no CSRF.
- There are no API keys, no bearer tokens, and no third-party OAuth in v1.

### 1.3 Authorization
| Level | Meaning |
|---|---|
| **Public** | No session required |
| **Authenticated** | Valid session + verified email (except `/auth/session/`, `/auth/logout/`, `/auth/verify-email*`) |
| **Owner** | Authenticated **and** the object belongs to `request.user` |

**Global rule (BR-02, BR-03):** every user-owned queryset is filtered by `request.user`; a non-owned object ID returns `404 not_found`, never `403`. `403` is reserved for "authenticated but not permitted" (unverified email, scheduled deletion, revoked consent, staff-only).

### 1.4 Pagination and filtering
```
GET /journal/?page=2&page_size=20
```
```json
{
  "count": 47,
  "page": 2,
  "page_size": 20,
  "total_pages": 3,
  "next": "/api/v1/journal/?page=3&page_size=20",
  "previous": "/api/v1/journal/?page=1&page_size=20",
  "results": []
}
```
- `page_size` default 20, max 100 (`400 invalid_page_size` above).
- `page` beyond the last page returns `404 page_out_of_range`.
- Ordering is fixed per endpoint and documented; no client-supplied `ordering` in v1.

### 1.5 Error envelope
```json
{
  "error": {
    "code": "validation_error",
    "message": "Some fields need attention.",
    "fields": {"intensity": ["Ensure this value is between 1 and 10."]},
    "request_id": "0f0b0c7e-6a1a-4c0e-9c1e-3f0f2f8a1b22"
  }
}
```
`fields` is present only for validation errors. `message` is safe to display. Field errors never echo submitted content.

### 1.6 Status codes
| Code | Used for |
|---|---|
| `200` | Successful read/update, idempotent upsert |
| `201` | Resource created; token/one-time secret issued |
| `202` | Accepted for async processing (export, reset request, deletion) |
| `204` | Deleted, no body |
| `400` | Validation failure, unknown field, confirmation mismatch |
| `401` | No/invalid session |
| `403` | Authenticated but blocked (unverified email, deletion pending, consent missing) |
| `404` | Not found **or not owned** |
| `405` | Method not supported (for example `PUT`; see §1.1) |
| `409` | State conflict (duplicate, already responded, token already used, edit conflict) |
| `410` | Token expired, invalid, or revoked |
| `415` | Unsupported request content type (only JSON is accepted) |
| `423` | Account locked |
| `429` | Rate limited (`Retry-After` header) |
| `500` | Unexpected server error (no internals) |

## 4. Authentication

### 4.1 `POST /auth/register/`
**Auth** Public · **Rate** 5/hour/IP · **Ownership** n/a

**Body**
| Field | Type | Required | Rules |
|---|---|---|---|
| `email` | string | yes | Valid email, ≤254, normalised lowercase |
| `password` | string | yes | ≥12 chars, not common, not entirely numeric, not similar to email |
| `accept_terms` | boolean | yes | Must be `true` |
| `accept_privacy` | boolean | yes | Must be `true` |
| `timezone` | string | no | IANA name; defaults to `UTC` |
| `display_name` | string | no | 1–80; defaults to email local part, title-cased |

**201**
```json
{"id":"6f1c…","email":"owner@example.com","email_verified":false,"onboarding_required":true}
```
**Errors** `400 validation_error`, `409 email_in_use`, `429 rate_limited`
**Side effects** user + profile + preferences + 2 consent records + verification token + audit, one transaction; email after commit.
**Never returns** password hash, tokens, or whether the email existed before (only the `409` on submit).

### 4.2 `POST /auth/login/`
**Auth** Public · **Rate** 10/min/IP and 5/min/email · **Ownership** n/a

**Body** `{"email":"…","password":"…"}`
**200** `UserSession` (§3.1)
**Errors** `401 invalid_credentials`, `403 deletion_pending`, `423 account_locked` (+`retry_after_seconds`), `429 rate_limited`
**Notes** Identical body/timing for unknown email and wrong password. An unverified user still receives `200` with `email_verified:false`; private endpoints then return `403 email_not_verified` until verification. On success: reset counter, rotate session, audit.

### 4.3 `POST /auth/logout/`
**Auth** Authenticated · **204** · Destroys the current session and clears cookies. Idempotent (`204` even if already anonymous).

### 4.4 `POST /auth/logout-all/`
**Auth** Authenticated · **204** · Increments `session_version` (all other sessions invalid), keeps the current session. Creates `security_alert` notification + audit.

### 4.5 `GET /auth/session/`
**Auth** Optional · **200** `UserSession` or `401 authentication_required`
Used by the SPA on boot. Includes `onboarding_required` and `deletion_scheduled_for`.

### 4.6 `GET /auth/csrf/`
**Auth** Public · **204** · Sets `csrftoken` cookie. Safe to call repeatedly.

### 4.7 `POST /auth/verify-email/`
**Auth** Public · **Rate** 10/hour/IP

**Body** `{"token":"<raw token>"}`
**200** `{"email_verified":true}`
**Errors** `410 token_expired`, `409 token_used`, `410 token_invalid`
**Ownership** Token resolves to exactly one user; no user id is accepted from the client.

### 4.8 `POST /auth/verify-email/resend/`
**Auth** Authenticated · **Rate** 3/hour/user
**202** `{"sent":true}` · `429 rate_limited` · No-op if already verified (`200 {"sent":false}`).

### 4.9 `POST /auth/password-reset/`
**Auth** Public · **Rate** 3/hour/email, 10/hour/IP
**Body** `{"email":"…"}`
**202** `{"message":"If that address has an account, a reset link is on its way."}` — identical for all inputs.
**Side effects** If account exists: token (60 min), email after commit, audit.

### 4.10 `POST /auth/password-reset/confirm/`
**Auth** Public · **Rate** 10/hour/IP
**Body** `{"token":"…","new_password":"…"}`
**200** `{"password_changed":true}` · `410 token_expired` · `410 token_invalid` · `409 token_used` · `400 validation_error`
**Side effects** password change, `password_changed_at`, all sessions invalidated, security notification, audit.

### 4.11 `POST /auth/password-change/`
**Auth** Authenticated
**Body** `{"current_password":"…","new_password":"…"}`
**200** `{"password_changed":true}` · `400` with `fields.current_password` or `fields.new_password`
**Side effects** other sessions invalidated, current session preserved, audit.

### 4.12 `POST /auth/email-change/`
**Auth** Authenticated · **Rate** 3/day/user
**Body** `{"new_email":"…","current_password":"…"}`
**202** `{"pending":true,"new_email":"n***@example.com"}`
**Errors** `409 email_in_use`, `400 validation_error`
**Side effects** `EmailChangeRequest`, verification email to the new address, notice email to the old address, audit. Address changes only on confirmation.

### 4.13 `POST /auth/email-change/confirm/`
**Auth** Public
**Body** `{"token":"…"}`
**200** `{"email":"new@example.com","email_verified":true}`
**Errors** `410 token_expired`, `410 token_invalid`, `409 email_in_use` (someone claimed it meanwhile), `409 token_used`.

### 8.5 `DELETE /support-requests/{id}/shares/{shareId}/`

**Note** The recipient page then shows a withdrawal notice; earlier viewing cannot be undone and the UI says so.

## 14. Privacy, consent, export, deletion

### 14.1 `GET /privacy/consents/`
**Auth** Authenticated · **Owner**
**200**
```json
{
  "current": {
    "terms_of_service": {"granted": true, "policy_version": "1.0", "granted_at": "…"},
    "privacy_policy": {"granted": true, "policy_version": "1.0", "granted_at": "…"},
    "wellness_disclaimer": {"granted": true, "granted_at": "…"},
    "email_notifications": {"granted": false, "revoked_at": "…"}
  },
  "history": [ /* ConsentRecord[] newest first, max 100 */ ]
}
```
**Notes** `current` lists **global (unscoped) consents only**, derived from the latest record per type. Scoped records (`support_request_sharing`, `contact_invitation`) are returned in `history` and are also shown on their parent request or contact. A missing type is absent from `current` (never assumed granted).

### 14.2 `POST /privacy/consents/`
**Auth** Authenticated · **Owner** · **Rate** 30/day/user

**Body** `{"consent_type":"…","granted":true|false,"policy_version":"1.0"?,"scope_type":"…"?,"scope_id":"…"?}`
**201** `ConsentRecord`
**Errors** `400 fields.consent_type` (unknown type, or a type not writable here per the table below), `400 fields.policy_version` (required for policy consents and must equal the current published version), `400 fields.scope_*` (scope required for `support_request_sharing`; must reference an owned request), `400 consent_required` (granting share consent here, or revoking a required policy consent), `404` for a non-owned scope.
**Rules**
| consent_type | Writable here | Notes |
|---|---|---|
| `terms_of_service`, `privacy_policy` | Grant only | Written by registration; this endpoint records re-consent when the policy version changes. Revocation is only via account deletion |
| `wellness_disclaimer` | No | Written by onboarding; informational acknowledgement |
| `support_request_sharing` | Revoke only | Grant is written by `POST /support-requests/` in the same transaction as the shares; revoking here withdraws all active shares for that request |
| `contact_invitation` | No | Written by WF-08 only; stored under the owner's user id as evidence of the invited person's response; the owner cannot revoke another person's consent |
| `email_notifications` | Yes | Mirrors `UserPreferences.email_notifications_enabled` |

**Revocation semantics** A revoking record is written with `granted=false` and `revoked_at=now()`; the superseded record also gets `revoked_at` set. The latest record per `(consent_type, scope)` is authoritative, and a missing record is never treated as granted.

### 14.3 `GET /privacy/export/`
**Auth** Authenticated · **200** `{"exports":[{id,status,requested_at,completed_at,expires_at,file_size_bytes,download_available}]}` (max 20, newest first).

### 14.4 `POST /privacy/export/`
**Auth** Authenticated · **Rate** 1/day/user
**Body** none
**202** `{"id":"…","status":"queued","requested_at":"…"}`
**Errors** `409 export_in_progress` · `409 deletion_pending` · `429 rate_limited`
**Side effects** `DataExportRequest` + audit; job builds the archive per `workflows.md` §18.

### 14.5 `GET /privacy/export/{id}/`
**Auth** Owner · **200**
```json
{
  "id":"…","status":"ready","requested_at":"…","completed_at":"…","expires_at":"…",
  "file_size_bytes":184320,"download_available":true,"download_count":0
}
```
**404** if not owned. `status` ∈ `queued|processing|ready|failed|expired`. On `failed`, `error_code` is a stable code (for example `export_too_large`), never an exception message.

### 14.6 `POST /privacy/export/{id}/download/`
**Auth** Owner · CSRF required · **Rate** 5/hour/user
**200** `{"download_url":"/api/v1/privacy/export/{id}/download/?token=<raw>","expires_at":"<now+5m>"}`

**Notes** The raw token is returned once and stored as a hash. The URL must be treated as a secret by the client (not logged, not put in `Referer`-generating anchors).

### 14.7 `GET /privacy/export/{id}/download/?token=`
**Auth** Owner session **and** valid token · **200** `application/zip`, `Content-Disposition: attachment`, `Cache-Control: no-store`
**Errors** `410 token_expired` / `409 token_used` (token expired or already used) · `401 authentication_required` (session missing) · `404`
**Side effects** `download_count=1`, token hash cleared, audit `export.downloaded`.
**Logging** The `token` query parameter is redacted by the logging filter (`security.md` §9.2).

## 17. Cross-cutting behaviours

### 17.1 Idempotency
Only `POST /support-requests/` supports a client idempotency key (`client_request_id`). Retries with the same key return the original request and never re-send email.

### 17.2 Optimistic concurrency
`PATCH /moods/{id}/` and `PATCH /journal/{id}/` accept `expected_updated_at`. A mismatch returns `409 edit_conflict` with `current_updated_at`.

### 17.3 Ownership enforcement pattern
```python
def get_queryset(self):
    return MoodEntry.objects.filter(user=self.request.user)

def get_object(self):
    return get_object_or_404(self.get_queryset(), pk=self.kwargs["pk"])
```
Every detail route uses this pattern; `IsOwner` is a second, redundant check. Non-owned IDs are indistinguishable from missing IDs.

### 17.4 Caching
| Resource | Header |
|---|---|
| Reference content (emotions, prompts, calm activities, policies, resources) | `private, max-age=3600` |
| User data | `private, no-store` |
| Health | `no-store` |

### 17.5 Validation philosophy
- Server-side validation is authoritative; client validation mirrors it for UX only.
- Lengths are enforced by both serializer and DB check constraints.
- Enumerations are validated against a single Python `TextChoices` class that matches the DB `CHECK` list in `database-design.md` §1.2.
- Referenced IDs must be owned; failures return field-level `400`, never `403`.

### 17.6 What the API never does
- Never returns another user's data, even partially.
- Never returns password hashes, token hashes, session keys, or internal file paths.
- Never accepts a `user_id` in a request body.
- Never includes journal content, mood notes, or support messages in errors or logs.
- Never sends email synchronously inside a request transaction.
- Never exposes a public feed, search across users, or contact discovery.

## 18. Versioning and deprecation

- Path versioning (`/api/v1`). Breaking changes require `/api/v2`; additive fields are allowed in v1.
- Clients must ignore unknown response fields.
- Deprecations are announced in `CHANGELOG.md` with at least one release of overlap and a `Deprecation` response header.
- `docs/openapi.yaml` is regenerated in CI; a diff fails the build if the schema changed without a changelog entry.
